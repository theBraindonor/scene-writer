# E001 — Pytest & Coverage Scaffold

## Requirements
- Add `pytest` and coverage tooling (`pytest-cov`) as dev dependencies of the project.
- Add a minimal placeholder module to each of the four core packages (`src/scene/cli`, `src/scene/agent`, `src/scene/data`, `src/scene/gui`) — including `src/scene/__init__.py` for the parent package — so each region has something real for a unit test to exercise.
- Add a top-level `test/` folder, sibling to `src/`, containing one test module per placeholder, with each test file's path mirroring its corresponding module's path under `src/` (e.g. `src/scene/data/__init__.py` → `test/scene/data/test_init.py`).
- Configure `pytest` (via `pyproject.toml`) so that running it with no extra flags:
  - discovers tests under `test/`,
  - measures coverage of `src/scene`,
  - always emits an HTML coverage report (e.g. to `htmlcov/`) by default, with no extra CLI flags required.
- Ignore generated coverage artifacts (`htmlcov/`, `.coverage`) in `.gitignore`.

## Rationale
This is the first encounter of the `c001-initial-tooling` campaign: it establishes the testing tool (`pytest`) and coverage reporting called for by the `unit-testing` lore, and gives every region a real (if trivial) module so the test suite has something to go green against before feature work begins. Mirroring `src/` paths under `test/` and defaulting to an HTML coverage report follows the just-updated `unit-testing` lore.

## Plan
1. Add `pytest` and `pytest-cov` to the project's dev dependency group in `pyproject.toml` (alongside the existing `crypts-and-commits` dev dependency), and update `pdm.lock`.
2. Create `src/scene/__init__.py` and `src/scene/{cli,agent,data,gui}/__init__.py`, each with a small, real placeholder (e.g. a `PACKAGE_NAME` constant or a trivial function) — enough to give a unit test a genuine assertion, not a no-op.
3. Create `test/scene/__init__.py` and `test/scene/{cli,agent,data,gui}/test_init.py`, each with a passing unit test asserting against its corresponding placeholder.
4. Add a `[tool.pytest.ini_options]` section to `pyproject.toml` setting `testpaths = ["test"]` and `addopts` to include `--cov=src/scene --cov-report=html` (plus `--cov-report=term` for console visibility) so a bare `pytest` invocation always produces the HTML report.
5. Add `htmlcov/` and `.coverage` to `.gitignore`.

## Verification
- Run `pdm run pytest` (or `pytest` inside the project's environment) with no extra arguments from the repo root and confirm: all tests pass, and an `htmlcov/index.html` report is generated without passing any coverage flags on the command line.
- Confirm no linting tooling is touched by this encounter — that is out of scope, reserved for a later encounter in this campaign.

### Message - 2026-08-18T02:07:07Z - John Hoff

Deviation from Plan step 3/4: did not create __init__.py files under test/scene/** as originally planned. With them present, pytest's default import mode resolved the empty test-tree "scene" package ahead of the real src/scene package, causing every "from scene.X import PACKAGE_NAME" to fail (ImportError pulling from the test package instead of src). Fixed by removing the test-tree __init__.py markers and adding --import-mode=importlib to addopts, which resolves test modules by file path instead of walking __init__.py chains, avoiding the src/test package-name collision. Verified: pdm run pytest with no extra flags collects and passes all 5 tests (100% coverage of src/scene) and writes htmlcov/index.html.

# E005 — Scene Length Attribute

## Requirements
- Update `docs/data-model.md`'s `SCENE` entity (ER diagram, column table, prose, and `CREATE TABLE` statement) to add an optional `length` `TEXT` column: free-form guidance on the expected prose length for the scene (e.g. a target character count or a qualitative size), presented to the LLM scene generator when present, alongside `required_actions`.
- Add a nullable `length` column to the `scene.data.Scene` ORM model, matching the updated `docs/data-model.md` definition — no constraint beyond nullability, consistent with the existing optional `heading`/`required_actions` columns.
- Extend `scene.core.scene`'s `create_scene` and `update_scene` to accept and persist an optional `length` argument, following the existing `heading`/`required_actions` parameter style.
- Extend the `scene-data scene` CLI commands (`create`, `get`, `update`) in `scene.cli.data` to expose `length` as an optional option/output field, matching the existing `--required-actions` treatment.
- Cover the new column and its plumbing with unit tests mirroring `src/` under `test/`, per the `unit-testing` lore, extending the existing `scene` model/service/CLI test modules rather than adding new ones (this is a single new optional attribute on an existing entity, not a new entity).

## Rationale
Scene construction currently has no way to record a desired prose length for a scene before drafting begins. Adding an optional `length` field to `scene` lets a human or an upstream construction step record that guidance (e.g. "about 800 characters" or "short") alongside the existing `required_actions` field, for later use by the scene-drafting phase's LLM generator. This is a narrow, additive schema change to an entity already fully delivered by `e002-scene-rendering-model-service-cli` — it extends that vertical slice rather than adding a new one, so it stays scoped to touching `Scene`'s existing model, service functions, and CLI commands (plus the data-model doc) rather than introducing new modules.

## Plan
1. Update `docs/data-model.md`: add `length` to the `SCENE` entity in the `erDiagram` block, add a `length` row to the `Scene` section's column table, add a sentence to the prose noting it is optional guidance for the scene generator, and add `length TEXT` to the `CREATE TABLE scene` statement (no `NOT NULL`/`CHECK`, matching `heading`).
2. In `scene.data.scene`, add `length: Mapped[str | None] = mapped_column(String, nullable=True)` to the `Scene` model, alongside the existing `heading`/`required_actions` columns.
3. In `scene.core.scene`, add a `length: str | None = None` parameter to `create_scene` (passed through to the `Scene` constructor) and to `update_scene` (assigned when not `None`, following the existing pattern for `heading`/`required_actions`).
4. In `scene.cli.data`, add a `length: str | None = None` option to `scene_create` and `scene_update`, and a `typer.echo(f"length: {scene.length}")` line to `scene_get`, following the existing `required_actions` treatment in each.
5. Update `test/scene/data/test_scene.py`, `test/scene/core/test_scene.py`, and `test/scene/cli/test_data.py` to cover creating a scene with `length` set, updating a scene's `length`, and the CLI exposing it end to end — extending the existing scene tests rather than adding new test files.

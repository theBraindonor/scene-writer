# E002 — Scene and Rendering Model, Service, and CLI

## Requirements
- Add SQLAlchemy ORM `Scene` and `Rendering` models to `scene.data`, matching `docs/data-model.md`'s `scene` and `rendering` tables and constraints:
  - `Scene`: `id`, `story_id` (FK to `story.id`, cascade delete), `position` (non-negative, unique per story), `heading` (optional), `description` (required, non-blank), `required_actions` (optional).
  - `Rendering`: `id`, `scene_id` (FK to `scene.id`, cascade delete), `body` (required), `is_active` (0/1), with a partial unique constraint/index guaranteeing at most one active rendering per scene.
- Add `scene.core` service modules for both entities, following the `story.py` pattern (functions operating on a caller-supplied `Session`):
  - `scene.core.scene`: create, get, list (scoped to a `story_id`), update, delete.
  - `scene.core.rendering`: create, get, list (scoped to a `scene_id`), set-active (deactivating any other active rendering for the same scene), delete.
- Extend the `scene-data` CLI (`scene.cli.data`) with two new Typer sub-command groups — `scene-data scene ...` and `scene-data rendering ...` — exposing the above through `scene.core`, following the same command shape as the existing `story` group.
- Cover the new models, service functions, and CLI commands with unit tests mirroring `src/` under `test/`, per the `unit-testing` lore, using an isolated (non-production) database for every test — including tests for the position-uniqueness and single-active-rendering constraints.

## Rationale
This is the second encounter of `c002-initial-data-model-and-crud`, extending the vertical-slice pattern established by `e001-story-model-service-cli` (model → core service → CLI) to `scene` and `rendering`, the next two entities in `docs/data-model.md`'s proposed schema. Scene and rendering are grouped into one encounter because a rendering only exists in relation to a scene, and both entities logically build on the `story` foundation `e001` already delivered.

## Plan
1. In `scene.data`, add `scene.py` defining the `Scene` model (matching `docs/data-model.md`'s `scene` table: FK to `story`, `position` with a non-negative check and a `(story_id, position)` unique constraint, `description` non-blank check, optional `heading`/`required_actions`).
2. In `scene.data`, add `rendering.py` defining the `Rendering` model (FK to `scene`, `body` required, `is_active` 0/1 check, and a partial unique index on `scene_id` where `is_active = 1`, mirroring the `idx_rendering_one_active_per_scene` index in `docs/data-model.md`).
3. In `scene.core`, add `scene.py` with `create_scene`, `get_scene`, `list_scenes(session, story_id)`, `update_scene`, and `delete_scene`, following `story.py`'s style.
4. In `scene.core`, add `rendering.py` with `create_rendering`, `get_rendering`, `list_renderings(session, scene_id)`, `set_active_rendering` (clears `is_active` on any other rendering for the same scene before activating the target one), and `delete_rendering`.
5. In `scene.cli.data`, add a `scene` Typer sub-app (`scene-data scene create|get|list|update|delete`) and a `rendering` Typer sub-app (`scene-data rendering create|get|list|set-active|delete`), registered on the existing `app` alongside `story`.
6. Add unit tests under `test/scene/data`, `test/scene/core`, and `test/scene/cli` covering both new models (including their constraints — position uniqueness, single active rendering), both new service modules, and both new CLI sub-command groups, all against an isolated test database.
